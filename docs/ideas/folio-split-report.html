🧭Why Now — and why this isn't native-first

The earlier native-first thesis (thin craft's commands into routes to Claude-native / third-party skills) was empirically refuted in PR #279: craft's /do router structurally can't dispatch cross-plugin, and 3/3 pilots showed craft's tools beat the generic replacements.

The folio split is orthogonal to that. It never needed cross-plugin routing — you invoke /folio:docs:* directly. The router wall is now a constraint the plan designs around (both plugins get their own router; neither bridges the wall), not a premise it depends on. This split stands purely on docs-maintenance merits: one cohesive, separable surface; halved count-cascade per plugin; folio reusable everywhere.

🔒5 Locked Decisions (the grill)

B1 · folio scope
Tools + shared docs-standards library; each project keeps its own content. Grounds on the existing docs-standards sibling repo.
Cost accepted: a third moving part to version alongside folio.
B2 · the release-coupling seam
Caller-based cut. docs:update + docs:changelog stay (release plumbing); site:deploy → raw shell; pure authoring → folio. Keeps craft's release self-contained, zero runtime dependency on folio.
Cost accepted: commands/docs/ splits across two plugins — a namespace seam users learn.
B3 · /do + /hub routing
craft drops DOCS/SITE from /do and /hub; folio ships its own /folio:do. The router never advertises a target it can't reach — honest, one model per plugin.
Cost accepted: no single-/do entry for docs; you switch plugins consciously.
B4 · count / bump tooling
Duplicate into folio. The split shrinks each cascade (~28 vs ~64), so per-repo tooling is lighter than today's combined 94.
Cost accepted: two small copies drift slowly — tolerable, independently versioned.
B5 · extraction + versioning
History-preserving git subtree split; staged; craft v4.0.0 (breaking) + folio v1.0.0, coordinated two-repo release.
Cost accepted: two-repo release choreography — done once, then each ships independently.

🚫What We Rejected (and the failure mode it maps to)

  • Move everything docs, release shells out to folio → the exact cross-plugin fragility native-first was refuted for. Release breaks if folio is absent.
  • Duplicate the release-plumbing subset into folio → drift = the deprecated-command-rich-body-trap, one level up.
  • folio launches scriptless → re-introduces the count-drift craft spent months killing.
  • Keep a DOCS pointer in /hub → advertises commands it can't run; craft must track folio's surface (doc-drift coupling).
  • Fresh copy, no git history → loses blame on the ~30 files most likely to need archaeology later.
